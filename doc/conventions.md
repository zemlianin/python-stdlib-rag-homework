# Conventions

## Границы изменений

Проект делается как учебный MVP. В код добавляются только те части, которые нужны для полного RAG pipeline. Решение должно быть простым, воспроизводимым и понятным проверяющему.

## Архитектура модулей

- `scripts/prepare_datasets.py` отвечает за подготовку исходного `datasets.json`.
- `scripts/ingest.py` отвечает за преобразование raw data в documents jsonl.
- `app/chunker.py` отвечает за нарезку текста на чанки.
- `scripts/build_index.py` отвечает за сборку индекса.
- `app/retriever.py` отвечает за поиск top-k фрагментов.
- `app/generator.py` отвечает за demo-ответ и отказ.
- `app/main.py` отвечает за Streamlit UI.

## Правила ответа

Система отвечает только по найденным фрагментам. Если релевантного контекста нет, ответ должен быть отказом. Нельзя выдумывать модули, функции, аргументы, периоды, переменные и источники.

## Тестовые требования

Тесты должны покрывать chunking, ingestion, retrieval и отказ generator при отсутствии релевантного контекста. Перед сдачей выполняется команда:

```bash
uv run pytest tests/ -v
```

## Правила по данным и зависимостям

Исходные данные должны иметь формат `data/raw/datasets.json` с массивом `datasets`. Каждая запись должна содержать `id`, `name`, `text`. Зависимости фиксируются в `pyproject.toml`. Сгенерированные файлы индекса не обязаны храниться в Git.
